# WebView 改造代码审查与整改目标

> 审查基线：`main` 分支，2026-10-15；相对之前的 `805a3f7` 审查基线。  
> 审查方式：仓库源码及现有测试静态审查，未执行 Windows/WebView2 实机测试。下列风险不代表已经在实机复现。

## 总体结论

改用 pywebview / WebView2 承载本地 Web UI 的方向合理。保留 `launcher.pyw` 的窗口与进程生命周期管理、`runtime.py` 的业务调度、`server.py` 的本机 API 和现有托盘/单实例机制。**不需要再次重构应用架构**。

本轮需处理两项 WebView 生命周期可靠性风险，并继续收尾此前未关闭的安装升级风险。

## P1：关闭确认事件可能被其他状态读取者消费

**依据：** `runtime.py` 的 `Runtime.state()` 在读取 `_close_prompt` 后立即将其设为 `False`，而 `/api/state` 并没有限定只能由内嵌 WebView 页面读取。其他合法客户端或并发请求可能先消费事件，使真正需要显示确认框的页面收不到通知。

**整改目标：**
- 关闭确认事件只由目标 WebView 窗口处理，不能被不相关的状态请求抢先消费。
- 页面刷新、长轮询重连、请求竞态下，待处理的关闭确认可被恢复或明确取消；不能无提示丢失。
- 关闭/托盘/退出行为保持现有语义；不要为了事件投递引入消息队列或额外服务。

**验收：** 构造两个同时请求状态的客户端、页面刷新或短暂断连、连续点击关闭等情况；确认事件最终由正确窗口展示或被明确取消，不会因非目标读取而丢失。测试至少覆盖原先“读一次就清零”的失败情形。

## P2：WebView 启动阶段异常未纳入回退/清理

**依据：** `launcher.pyw` 的 `Launcher._run_ui()` 对 `import webview` 与 `create_window()` 失败有回退处理，但 `webview.start()` 在异常捕获范围之外。运行时初始化 GUI 失败可能使主进程异常退出，未走正常停机流程。

**整改目标：**
- 明确并实现 `webview.start()` 启动失败时的行为：安全回退浏览器窗口，或明确报错并完成退出清理。
- 若有部分创建的 WebView 窗口或宿主状态，回退时不得留下“假装有可控窗口”的引用。
- 确保托盘、HTTP 服务、调度线程和图库更新子进程最终有确定的生命周期；避免半启动状态。
- 不改变正常情况下的窗口操作与单实例唤起行为。

**验收：** 模拟 `webview.start()` 抛异常、`create_window()` 抛异常、模块不可用和正常关闭；断言回退/退出路径、宿主引用、后台组件清理符合设计，并在 Windows 实机核对至少一次启动失败或运行时不可用场景。

## P2：安装升级可靠性仍有未关闭问题（承接之前审查）

**依据：** `installer.pyw` 在进入安装阶段前检查一次实例，随后异步开始逐文件复制；检查之后目标程序可重新启动，复制中途失败也可能留下混合版本。详见 [此前最终整改建议](final-review-recommendations.md)。

**整改目标：**
- 修改安装目标文件前重新确认应用未运行；必要时采用局部升级排他协调，不能仅依靠单次向导检查。
- 先准备待安装程序文件和可恢复备份，复制失败时尽量恢复原程序文件；失败或恢复不完整时明确提示。
- 保留原有 `config.json`、`library/`、`cache/` 和 `logs/` 等用户数据；不得以查杀无关进程解决升级问题。
- 使用轻量方案，不增加通用安装事务框架。

**验收：** 模拟“向导检查通过后、实际复制前程序重新启动”和“复制中途 I/O 失败”，确认升级被安全拒绝或能恢复原版本，并验证用户数据未受损。Windows 实机执行运行中升级、退出后升级及失败恢复验证。

## 执行规则与完成标准

1. 先核对最新源码及相关测试；用针对性测试确认问题仍成立，再做最小修复。如果审查判断与实际不符，记录证据，不为满足文档硬改代码。
2. WebView 正常关闭、记住选择、最小化到托盘、托盘退出、重复启动、浏览器回退以及壁纸轮换行为均不得回归。
3. 补足多客户端竞争、状态重连、GUI 启动异常、安装竞争窗口、复制失败恢复测试，并执行现有全量回归测试。
4. 涉及 pywebview/Windows API 的关键行为应在 Windows 实机验证；未执行的测试明确标注“未验证”，不可仅凭 mock 单测声称通过。
5. 每项提交说明写明修复范围、测试结果与尚存风险。避免额外模块拆分、新依赖、UI 重设计或业务规则变更。
6. 以上项目完成后停止本轮重构整改；不因非阻断性建议继续扩展范围。

### 验收清单

- [ ] 关闭确认不会被无关状态请求消费，刷新与重连行为可预测。
- [ ] WebView GUI 启动失败有可验证的回退或清理路径。
- [ ] 安装升级的重新检查与失败恢复有效，用户数据安全。
- [ ] 原有窗口、托盘、轮换、图库更新、配置功能测试没有回归。
- [ ] Windows 实机验证记录真实、完整，未测项不标记为通过。
