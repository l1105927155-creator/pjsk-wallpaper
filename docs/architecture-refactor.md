# 架构重构方案：Tkinter → 本地 Web App

## 目标与边界

把 pjsk-wallpaper 从 Tkinter 主窗口迁移为本机 Web UI，保持 Windows 桌面壁纸、锁屏壁纸与图库更新的现有行为。优先做职责分离和可验证的迁移，不以重写核心业务为目标。参考同一作者的 kanban 项目：原生 HTML/CSS/JavaScript + Python 本机 HTTP 服务 + 浏览器应用窗口。这里**不需要** MCP、账号、多用户、云服务、数据库、Electron 或大型前端框架。

### 必须保留的行为

- Windows 10/11 本机运行；无管理员权限完成日常壁纸切换。
- 桌面与锁屏独立启停、独立间隔、独立随机序列；随机轮次内不重复（遵循现有 Rotator 行为）。
- 桌面 SystemParametersInfo 切换与原有 explorer 淡入处理；锁屏 PowerShell/WinRT 设置。
- 切换只读取本地图库，无运行时联网；网络只发生在用户或间隔触发的图库更新。
- pjsk / custom 图片源可选；添加自定义图片、适配屏幕分辨率、打开图库目录；pjsk 上限与 FIFO 行为不变，自定义图片不受该上限影响。
- 图库手动更新、间隔更新及原有角色、组合、稀有度、数量等筛选能力；更新日志与进度/错误可查看。
- Windows 开机自启、桌面/开始菜单快捷方式、系统托盘与托盘内“下一张 / 退出”动作。
- 配置、library、cache、logs 的既有数据目录与兼容性。升级不得清空或移动用户图库。
- 关闭/最小化 UI 窗口不停止轮换；用户明确从托盘退出才结束进程。轮换/更新仍只在后台进程运行时执行。

## 已有结构与问题

- `wallpaper.pyw`: `App(tk.Tk)` 包含控件、配置采集、约 20 秒 tick、轮换定时、图库更新子进程和托盘回调；业务状态依赖 `tk.*Var`。
- `core.py`: 配置、Windows 壁纸 API、图片处理、图库路径、Rotator 与 Windows 系统集成。尽量复用。
- `gallery_update.py`: 独立图库更新脚本。尽量复用。
- `tray.py`: ctypes 系统托盘，复用但将“显示 Tk 窗口”改为“打开/聚焦 Web 应用窗口”。
- `installer.pyw`、`start.bat`、`安装助手.bat`: 安装与启动入口，需随新进程生命周期调整。
- `set_lockscreen.ps1`: 保留。

**主要风险**：仅替换 Tkinter 视图仍会导致后台调度依赖 UI 事件循环。须先把时间、状态、配置读写及任务执行从控件中拆出。

## 目标结构（建议，实际名称可按最小改动调整）

```text
app/                  # 静态 Web UI: index.html, CSS, JS, assets
server.py             # 只绑定本机的 HTTP API、静态资源、启动入口
runtime.py            # 独立的轮换和更新调度、运行时状态、同步/互斥
core.py               # 复用 Windows API、配置、图片和 Rotator
gallery_update.py     # 复用现有图库更新逻辑
tray.py               # 托盘入口与后台退出
launcher.pyw          # 无控制台启动、单实例、应用模式窗口打开
installer.pyw         # 安装路径、快捷方式、开机自启适配
set_lockscreen.ps1    # 原样保留
library/, cache/, logs/, config.json
```

`server.py` 与 `runtime.py` 可以合并，只要职责清晰且无需增加多余抽象层。不要同时留下两套轮换调度器。

### 运行模型

```text
浏览器 app 窗口 ── HTTP ──> localhost Python 服务 ──> Runtime ──> core / gallery_update
                                           │
                                           └── 托盘控制 / 系统配置
```

- **Python 后台进程是唯一业务状态的权威来源**：管理调度、已保存配置、当前任务与下一次触发时间。Web UI 只是展示/发送命令，不承担任何定时任务。
- Web 页面关闭、刷新、崩溃或失去网络连接，不影响正在运行的轮换任务。
- 独立桌面/锁屏随机序列与定时器不得相互重置；手动切换对下一次定时触发的影响应与旧版一致，需先用原版行为测试确认。
- 配置变更通过 API 校验并持久化；不要依靠前端每 20 秒自动保存。调度器读取内存中的一致配置快照，保存应保证不会写入截断 JSON。
- 图库更新必须避免重入；状态、成功/失败和完成时间由后端记录。不要阻塞 HTTP 请求线程或调度器。
- Windows 托盘与 HTTP 服务共享同一运行时；确认相关 Windows API/线程限制，避免多进程分别持有不同计时器。
- 启动器应复用现有实例，并打开/聚焦浏览器 app 窗口；避免重复启动产生两个轮换进程。浏览器退出仅关闭界面；托盘“退出”需清理 HTTP 服务、定时任务与子进程。
- 浏览器 `--app` 模式优先复用已安装的 Edge/Chrome；正常浏览器页面可作为回退。不强制随软件分发浏览器。

### HTTP API（建议语义，不拘泥于命名）

| 类别 | 操作 |
| --- | --- |
| 状态 | `GET /api/state`：配置、图库计数、桌面/锁屏轮换状态、下次执行时间、更新任务状态 |
| 配置 | `PATCH /api/config`：仅允许已定义字段，校验数据类型与上下限，写盘后应用到调度器 |
| 切换 | `POST /api/wallpaper/desktop/next`、`POST /api/wallpaper/lock/next` |
| 图库 | `GET /api/gallery`：分页/筛选；`GET /api/images/<id>`：本地预览；`POST /api/gallery/custom`：上传；删除能力仅在确认需求后加入 |
| 更新 | `POST /api/gallery/update`：触发一次；`GET /api/gallery/update/status` |
| 系统 | `GET /api/system`、`POST /api/system/autostart`、`POST /api/system/open-folder`、`POST /api/system/create-shortcuts` |

所有具有写入/系统副作用的接口应有明确的成功、失败与任务忙碌响应。前端不可自行拼接绝对文件路径作为 URL。图库以服务端受控 ID 映射到已知本地目录，阻断 `../`、符号链接越界和任意文件读取。

### 本地安全边界

服务默认仅绑定 `127.0.0.1`，不开放局域网或公网，不引入登录系统。**仅监听 loopback 不足以防止恶意网页访问本地服务**：对写接口验证 Host / Origin，并要求自定义请求头或同源令牌，拒绝跨站表单及不可信 CORS；控制请求体/上传大小、文件类型、文件路径，防止任意目录访问。不要开放任意 shell 命令执行或用户传入路径的任意程序启动。端口被占用时不得误连到别的服务；启动器验证本应用实例身份。

## 分阶段开发

1. **建立行为基线**：阅读当前实现，列出并记录每一项旧版操作实际效果；准备可重复的 Windows 手工验收步骤与核心单测。先备份用户 `config.json` 和 `library/`。
2. **抽离业务状态与调度**：不更改 UI 时先使业务可在 Tkinter 以外运行，测试桌面/锁屏轮换互不干扰、更新互斥、配置持久化、停止清理。
3. **实现本机 HTTP 服务与启动器**：先用最简页面覆盖状态、配置、两类“下一张”、图库更新，确保无 Tk 窗口仍可长期运行并通过托盘退出。
4. **替换为正式 Web UI**：依照 [UI 重构方案](ui-refactor.md) 开发静态页面，对接 API；移除旧 Tkinter 主界面和不再需要的冗余状态。
5. **安装与迁移验收**：更新安装助手、快捷方式、启动脚本和 README，升级已有安装目录不破坏数据；Windows 10/11、重启、重复启动与异常恢复全部走查。

每阶段保持程序可运行并单独提交，失败时能回退。不要提前开展与重构无关的图库数据源重做、权限框架、插件平台等工作。

## 验收标准

- [ ] 不启动 Tkinter 窗口，Web UI 能查看/修改所有旧版配置，并能手动触发所有旧版操作。
- [ ] 页面关闭、刷新和浏览器崩溃后，桌面/锁屏轮换及图库更新调度仍继续；再次打开显示真实状态。
- [ ] 旧版桌面/锁屏独立性、轮次去重、淡入、图片处理、更新频率和 FIFO 语义保持一致；人工确认锁屏修改生效。
- [ ] 启动多次只有一个后台调度实例；托盘退出后不残留后台服务或更新子进程。
- [ ] 网络断开时，本地图像切换照常；图库更新失败有反馈且不会破坏现有图库。
- [ ] 原 `config.json`、`library/` 数据迁移后可用；保留用户自定义图片、配置和缓存/日志，升级与重新安装场景已验证。
- [ ] API 校验、跨站访问阻断、路径遍历拒绝、恶意/超限上传拒绝通过测试。
- [ ] README 和安装流程与实际启动/退出行为一致；Windows 实机验证后再声称完成，不能只以 HTTP 单测代替 OS 行为测试。
