# UI 重构方案：本地 Web 壁纸管理界面

## 目标

以原生 HTML + CSS + JavaScript 替换 Tkinter/ttk UI，获得更好的视觉层次、图库体验与响应式布局。参考 `kanban` 项目的技术路线和浏览器应用模式，但**不照搬任务看板的信息架构**。Web UI 是本机壁纸服务的控制台，不是在线壁纸站点；在保持旧功能完整的前提下提升可用性。

## 设计原则

- **壁纸是内容主角**：突出图片预览与当前选中的壁纸；重要操作比参数堆叠更容易找到。
- **操作与设置分离**：高频“下一张”、更新、图库预览在前；定时与高级筛选放在清晰的设置区域。
- **响应式布局**：桌面宽屏充分利用空间，窗口缩小时卡片、侧栏和表单合理重排；不得水平溢出、遮挡按钮或需要拖宽到固定尺寸才可用。
- **状态可信**：上次/下次切换时间、图库数量、更新中的进度与错误以 Python API 为准。页面刷新后状态一致。
- **轻量实现**：原生 HTML/CSS/JS，避免无必要的构建链、框架、在线 CDN、第三方字体和重型 UI 组件依赖。
- **本地可用**：静态资源全部本地打包；离线仍能查看图库和切换本地壁纸。

## 建议的信息架构

### 首页 / 概览

- 桌面壁纸与锁屏壁纸两个视觉明确的预览区；图片可从后端返回的当前壁纸路径映射或状态中获得，无法识别时展示占位而非伪造预览。
- 各自独立：启用状态、轮换间隔、上次/下次切换、显著的“下一张”。
- 简洁的图库数量与最近更新状态；“立即更新”入口与任务中反馈。
- 页面状态不应该依赖定期写入配置；读取后端数据刷新 UI 即可。

### 图库

- pjsk/custom 图片分类或筛选、缩略图网格、点击大图预览；图片数量较多时分页/按需加载，避免一次性加载全量原图。
- 添加自定义图片：文件选择，条件允许时支持拖放/批量；显示格式限制、处理中与失败反馈。
- 显示图库来源选择开关（pjsk/custom）并与实际轮换规则保持一致；两种来源都关闭时阻止无效配置或明确提示旧版对应行为。
- “打开 pjsk/custom 目录”沿用后台系统操作接口。删除图片、收藏、手动重排等**不是本轮必需功能**，不要自作主张增加。

### 设置

- **轮换**：桌面与锁屏各自启停和间隔（单位分钟）。
- **图库更新**：立即更新、间隔更新开关/分钟、每次张数、最低稀有度、角色、组合、pjsk 容量上限；保留旧配置语义与合法范围。
- **系统**：开机自启、创建快捷方式、打开相关目录、必要的日志/错误信息。
- 区分“设置已保存”和“执行已完成”。异步更新不会因 HTTP 返回启动成功就标记为成功。

## 页面交互与视觉要求

- 可以采用深色、卡面主题、克制的色彩点缀；视觉风格保持一致，不要为装饰牺牲可读性。
- 统一字号层级、间距、卡片圆角、按钮与开关样式；控件有 hover/focus/disabled/busy 状态；键盘可操作，提示文本和输入项有关联。
- 建议 CSS Grid/Flex + media queries；在约 1280px 桌面窗口、800px 窄窗口及 420px 小窗口下人工检查。尺寸仅为验证样例，不是强制设计断点。
- 长文本、更新错误、无图库图片、网络断开（图库更新失败）、加载中都有合理显示；失败操作应保留用户输入并提供重试。
- 下一张按钮应防重复点击；图片预览可采用适当裁切，但不得影响原图的真实壁纸应用。
- 禁止在前端持有任何系统文件绝对路径作为可写权限；文件操作通过后端受控接口。
- 顶部/侧栏的导航结构由页面实际复杂度决定。可以用单页分区，不必强行拆多路由或开发 SPA 框架。

## 与后端的接口契约

依据 [架构重构方案](architecture-refactor.md) 中的 API 语义。前端仅通过同源 HTTP 调用后端，获取图库缩略图、应用状态和配置。所有设置改动都要在后端成功保存后更新为“已保存”，失败时恢复或明确标记未保存。轮换倒计时可以前端展示，但必须基于后端返回的绝对时间并定期校准，不独立决定任务触发。

## 实施次序

1. 先完成简陋但完整可操作的页面，映射全部原 GUI 功能，确认业务不回退。
2. 建立统一 CSS 变量、布局和表单组件；改善首页与图库的视觉结构。
3. 完善小窗口响应式、错误/空状态、键盘可访问性与交互反馈。
4. 在 Windows 实际浏览器 app 窗口测试，并修复安装后资源路径与启动问题。

## UI 验收清单

- [ ] 桌面、锁屏的预览/启停/间隔/下一张分别正确，不会串用状态。
- [ ] pjsk/custom 来源选择、添加图片、图库数量、打开目录均可用。
- [ ] 更新筛选参数、数量、更新开关与间隔、立即更新及其状态展示齐全。
- [ ] 开机自启、快捷方式、pjsk 上限和旧版状态/错误展示得到保留。
- [ ] 页面刷新与重开不丢配置、不停止计时，状态从后端恢复。
- [ ] 1280px、800px、420px 示例宽度及 Windows 缩放环境下没有横向溢出或重叠；主要交互可操作。
- [ ] 无图库、更新失败、网络断开、任务繁忙、上传无效文件等异常情况有准确反馈。
- [ ] 页面所用 JS/CSS/图片资源离线可加载，无外部 CDN 依赖。
- [ ] 不改变原壁纸服务的随机、轮换、下载和持久化规则；新增功能不超出本轮范围。
